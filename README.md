# GraphRAG

> **A High-Performance, Evidence-Grounded Knowledge Assistant Powered by Property Knowledge Graphs, Dense Vector Search, and Groq LLM Inference.**

---

## 📌 Overview

**GraphRAG** is a full-stack, production-grade retrieval-augmented generation application designed to eliminate LLM hallucinations through structured graph traversal and verifiable source citations.

By extracting entities, claims, and semantic relationships from uploaded documents and indexing them into an explicit property graph in **Neo4j**, GraphRAG allows users to ask complex, multi-hop questions over their technical corpus with complete provenance down to the exact sentence excerpt.

---

## 🚀 Key Capabilities

- **Multi-Format Ingestion**: Ingests `.txt`, `.md`, `.pdf`, `.json`, and `.csv` documents with deterministic sliding-window chunking, SHA-256 provenance hashes, and page/section metadata preservation.
- **Provenance-Safe Knowledge Graph**: Models explicit `Document`, `Chunk`, `Entity`, and `Claim` nodes in Neo4j with transactional writes, idempotent re-ingestion, and safe document deletion that preserves shared entities.
- **Canonical Entity Resolution**: Normalizes entity identities independently of document titles, handling aliases gracefully and preventing false mergers between distinct concepts.
- **Hybrid Retrieval Pipeline**: Combines exact/normalized entity matching, lexical keyword matching, 384-dimensional dense vector semantic search, and bounded multi-hop Cypher traversals.
- **Strict Server-Side Citation Validation**: Every citation generated by the LLM is verified server-side against actual retrieved chunks. Hallucinated citation IDs are discarded before presentation.
- **Prompt-Injection Defense**: Treats all document content as untrusted data within strict system prompts, preventing adversarial prompt overriding.
- **Interactive Web Interface**: Built with Next.js 15 and Tailwind CSS, featuring a Document Library, Ingestion Status Badges, Grounded Chat with clickable citation chips, and an Evidence Inspector Drawer.
- **Robust Developer Ergonomics**: Strict TypeScript across backend and frontend, centralized Zod validation, structured logging with Request IDs, automated health endpoints, and 100% deterministic Vitest test suites.

## ⚡ Quick Start

### 1. Prerequisites
- **Node.js**: `v20+` or `v22+` (v24 supported)
- **Docker**: For running Neo4j Community Edition
- **Groq API Key**: Free API key from [Groq Console](https://console.groq.com/keys)

### 2. Configure Environment
Copy the example configuration to `.env`:
```bash
cp .env.example .env
```

Configure your `.env` file:
```ini
# Server
PORT=4000
WEB_ORIGIN=http://localhost:3000

# Groq LLM
GROQ_API_KEY=gsk_your_groq_api_key_here
GROQ_MODEL=llama-3.3-70b-versatile

# Neo4j Database
NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=graphrag_secret_password

# Embeddings
EMBEDDING_PROVIDER=local-minilm
EMBEDDING_MODEL=all-MiniLM-L6-v2
```

### 3. Start Neo4j (Docker Compose)
```bash
npm run docker:up
```
- **Neo4j Browser**: [http://localhost:7474](http://localhost:7474) (Username: `neo4j`, Password: `graphrag_secret_password`)
- **Bolt Port**: `bolt://localhost:7687`

*(Note: If Docker is not running, the application automatically uses an in-memory graph repository for local evaluation).*

### 4. Run the Application
In terminal 1 (Backend API):
```bash
npm run dev:api
```

In terminal 2 (Frontend Web App):
```bash
npm run dev:web
```

Open **[http://localhost:3000](http://localhost:3000)** in your browser.

## 📖 Using the Application

1. **Ingest Documents**:
   - Click the **Upload** button to upload `.txt`, `.md`, `.pdf`, `.json`, or `.csv` files (up to 10MB), or paste raw text.
   - The system validates the content, splits text into overlapping chunks, generates dense vector embeddings, and extracts entities & claims.
2. **Inspect Ingestion Status**:
   - Documents display real-time status badges (`Queued`, `Extracting Graph`, `Indexed`, or `Failed`).
   - Click any document to inspect its file metadata, chunk count, and SHA-256 provenance hash.
3. **Ask Grounded Questions**:
   - Type natural-language queries into the **Grounded Graph Assistant** chat panel.
   - The engine performs hybrid retrieval (lexical + vector + graph traversal) and generates an answer strictly grounded in the retrieved sources.
4. **Audit Citations**:
   - Click on any citation badge (e.g. `[1]`, `[2]`) in the answer to slide out the **Evidence Drawer**.
   - Review the verbatim source passage, document title, and graph relationships supporting the claim.

## 🧪 Testing & Quality Gates

Run the test suite:
```bash
npm run test:api
```

### Test Coverage Highlights
- **Unit Tests**:
  - Sliding-window text chunking and boundary overlap.
  - Normalization and deterministic canonical entity ID resolution.
  - Zod validation schemas for inputs and model outputs.
  - 384-dimensional embedding normalization and cosine similarity scoring.
  - Server-side citation validation (filtering out hallucinated citation IDs).
- **Integration Tests**:
  - Safe document deletion (verifying shared entities referenced by other documents remain intact).
  - API endpoint validation, pagination, and standardized error envelopes (`/health/live`, `/api/v1/documents`, `/api/v1/chat/query`, `/api/v1/graph/stats`).
- **End-to-End Tests**:
  - Complete vertical slice: upload -> chunking -> extraction -> hybrid retrieval -> grounded answer with verifiable citations.
